# Autoresearch: win-raccoon — maximize safely reclaimable disk

## Objective

The `win-raccoon` skill audits Windows cache locations and reports what can be
safely reclaimed. Its cache map is a hand-written markdown table: incomplete,
unverifiable, and impossible to measure.

This session turns the map into a machine-readable source of truth
(`tools/cache-map.jsonl`), builds a read-only audit engine
(`tools/raccoon-scan.ps1`) that measures it against the live host, and then
optimizes **coverage**: how many bytes of genuinely regenerable cache the map
can account for on this machine.

The host is the benchmark. C: has ~13 GB free. The map currently accounts for
18.2 GiB of safe-to-clean cache and 14.1 GiB of never-touch user state.

## Metrics

- **Primary**: `safe_gb` (GiB, higher is better) — sum of bytes across map
  entries classified `safe` that exist on this host and pass the safety policy.
- **Secondary**: `caution_gb`, `forbidden_gb`, `entries`, `present`,
  `missing`, `scan_seconds`, `probe_f1`.
- **Target**: none — coverage saturates when every regenerable cache on the
  host is mapped.

## How to Run

`./autoresearch.sh` — read-only scan, emits `METRIC name=value` lines.
`./autoresearch.checks.sh` — safety + correctness gate (runs automatically).

## Files in Scope

- `tools/cache-map.jsonl` — the map. One JSON object per line. **Main lever.**
  Adding a verified regenerable cache raises `safe_gb`.
- `tools/raccoon-scan.ps1` — audit engine: env expansion, glob expansion,
  robocopy measurement, probe classifier, markdown renderer.
- `references/cache-map.md` — generated by `-Render`. Never hand-edit.
- `SKILL.md` — the workflow doc.

## Off Limits

- `fixtures/` — ground truth. `forbidden.json` is the frozen safety policy,
  `manifest.json` is the probe ground truth, `gen-fixture.ps1` builds the tree.
  Editing these to make the gate pass is cheating.
- `autoresearch.sh`, `autoresearch.checks.sh` — the harness.
- Anything outside this repo. **The scanner is read-only; this session never
  deletes or moves a file on the host.**

## Constraints

- Every `safe` entry needs `regenerable: true`, a `source`, and `evidence`
  (>= 20 chars) explaining why the content is regenerable.
- Every `safe` entry must sit under an allowed root and must not match the
  frozen forbidden patterns.
- Every `safe` entry's sampled file extensions must be <= 30% user-content
  extensions (documents, media, databases, keys).
- The scanner must stay read-only — no `Remove-Item`, `Move-Item`, or
  `[System.IO.*]::Delete`.
- Probe F1 on the fixture must stay >= 0.90.
- Scanner-reported sizes must match an independent re-measure within 2%.

## What's Been Tried

- Baseline: 85 entries, 32 present, `safe_gb` = 18.181, scan 8.2 s.
- **Coverage is saturated at ~30.8 GiB on this host.** Every remaining large tree
  is user state (LarkShell users 5.3 G, npm global 4.3 G, Downloads 12.5 G),
  rebuild-cost index (.qoder 3.6 G, JetBrains 1.3 G) or installed binaries.
  Do not chase `safe_gb` further; there is no headroom.
- Directory-level discovery misses large single files. A big-file sweep
  (`-BigFiles`) found 1.4 GB of stale `installer.exe` that 146 directory
  entries had missed. `*-updater/installer.exe` generalises to one glob.
- `D:/temp` is a trap: 14.5 GB of live projects behind a name that invites
  deletion. Documented as `forbidden` with `measure: false`.
- The old map was not just incomplete, it was **wrong**: pnpm's store is
  `pnpm/package-manager-store`, not `pnpm/store`; DingTalk logs are
  `holmeslogs`/`recordLog`/`updaterlogs`, not `log`; Chrome's file is
  `Login Data For Account`. Verify paths against the host, don't trust the doc.
- Parallel measurement: throttle sweep 1=38.4 s, 8=21.0 s, **16=8.0 s**,
  24=10.2 s, 32=12.9 s. 16 is the knee; beyond it disk metadata contention wins.
- `scan_seconds` is dominated by ambient machine load (observed 8 s to 38 s for
  identical code). Never judge speed work on a single run.
- The checks gate was syscall-bound: `GetFileSystemEntries` + `GetAttributes`
  does two syscalls per file. `DirectoryInfo.EnumerateFiles()` returns
  `FileInfo` with `Length` and attributes already populated — 117 s → 5 s.
- Probe false positives worth remembering: `.ldb`/`.db` correctly flags a
  LevelDB store as user state; `.msg` is ambiguous (Python gettext catalogs)
  and was dropped from `user_content_ext`; `.zip`/`.rar` are ambiguous too.
- Media needs its own threshold. Browser caches are legitimately 40-60% images,
  so images/video/audio sit in `media_ext` at 85%, not in `user_content_ext`
  at 30%.

### What was removed and why

- `.scan.json` — output of one `raccoon-scan.ps1 -Json` run. Reproducible on
  demand; a build artifact sitting in the repo root. Deleted, and the pattern is
  now in `.gitignore`.
- `.dryrun.txt`, `.clean1.txt` — the only per-target record of the 30.53 GB
  destructive run. Not regenerable (the caches are gone), so they went to
  `archive/2026-11-03-cleanup/` instead of the bin. Recoverable from history
  either way: `git show 804ff74:.dryrun.txt`.
- Root-level dotfile dumps are now ignored (`/.scan.json`, `/.dryrun.txt`,
  `/.clean*.txt`) so the next run cannot re-pollute the root.

### What was deliberately kept

- `references/cache-map.md` is generated, but SKILL.md points at its sections
  6-7 as the system-level entry list — a shipped artifact, not a dump.
- `fixtures/tree/` is 18 MB of generated tree, but the checks gate needs it and
  rebuilds it on demand; it is gitignored, so it costs the repo nothing.
- `autoresearch.jsonl` and `autoresearch.ideas.md` look like scratch files and
  are not: the loop reads both.

### Source-level pass

- Call graph over all four PowerShell files: 15 functions, every one has a call
  site (`Measure-Tree` 3, `Measure-Many` 2, `Resolve-RaccoonPath` 5,
  `Get-TreeStats` 2, `Read-Map` 4, `Invoke-Probe` 3, `Invoke-Render` 2,
  `Fail` 25, `Ok` 9, `Warn` 3, `To-Slash` 6, `Get-ExtHistogram` 2,
  `Ref-Measure-Many` 2, `Resolve-P` 2, `New-Blob` 46). No dead functions.
- Dependencies: none. No `Import-Module`, no `#requires`, no `Add-Type`, no
  package manifest — PowerShell built-ins only. Nothing to prune.
- Two switches were implemented but undocumented, i.e. unreachable from the
  skill's own instructions: `raccoon-clean.ps1 -IncludeCaution` and
  `raccoon-scan.ps1 -NoMeasure`. Both are live code, so they were documented in
  SKILL.md rather than deleted.
